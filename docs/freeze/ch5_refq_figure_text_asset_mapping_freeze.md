## 5. Main/supplement separation and namespace

Main figures and supplementary items have separate directories and independent
mapping registers. A main-only change updates only the main register; a
supplementary-only change updates only the supplementary register. Both are
updated only when a shared baseline change materially alters both mappings.

```text
ANALYSIS_STAGE_NAMESPACE = S1, S2, S3, S4, S5, S6, S7
SUPPLEMENTARY_FIGURE_NAMESPACE = Supplementary Figure S1; Supplementary Figure S2; Supplementary Figure S3; Supplementary Figure S4; Supplementary Figure S5
NAMESPACES_INTERCHANGEABLE = NO
MAIN_SUPPLEMENT_NAMESPACE_SEPARATED = YES
```

Use qualified language such as `analysis stage S5` for a pipeline stage and
`Supplementary Figure S5` for the figure namespace. No current Figure 0 asset
was found in the accepted repository render tree; the historical migration
record classifies its older scaffold as internal/non-paper, so Figure 0 is in
neither current register.

## 8. Maintenance rules

- Update the main register only for changes to Figure 1–4 manuscript identity,
  body/caption references, assets, panel structure, or authority/provenance.
- Update the supplementary register only for changes to its inventory, render
  status, assets, references, or provenance.
- A main-only change does not require rewriting unrelated supplementary
  records; a supplementary-only change does not require rewriting main
  records.
- Update both only if a shared baseline change materially changes both maps.
- Never treat S1–S7 analysis stages as Supplementary Figure S1–S5 IDs.
- Never infer that reserved S5 has been rendered.
- Do not use Phase 2-B as a current asset or panel authority.
